## 3. 已发现的具体可修问题

### A. visual 自检文案已经过期

当前 merged `visual/index.html` 的“自检状态”仍写：

> 尚未宣称 PASS。当前正在按最新 upstream validator 修复并准备正式 manifest / self_check。

但 exact v0.5 head 已经 canonical self-check 全 PASS，官方 CI 也已 PASS。这是 participant-controlled 的内部状态不一致。v0.6 必须中英同步修正为真实的 `formal-review-ready / four gates PASS`，同时继续强调 provisional geometry 不因 PASS 升格为官方数据。

### B. 实施可行性仍缺“资源数量级 + 权责路径”

v0.5 已有“项目—空间—建议角色—前置条件—启动/停止阈值—维护责任—KPI”，但 proposal 明确把真实主体、预算、合同留待确认；当前没有形成可让评审快速核对的：

- RACI / accountable role 分层
- 概念成本区间与数量基础
- FTE / 运维频率 / 维护资源量级
- 许可/审批/安全/保险等前置门
- day-one opening drill / fault cards / closing decision
- pilot 时间窗与 GO / REVISE / STOP 决策收据

这些都可以在“不伪造真实合同/预算”的前提下写成**概念数量级 + unknown/confirm-before-start**。

### C. 公共利益人物画像对弱势群体还不够显性

当前 proposal 的 5 类 persona 覆盖居民、学生/科研、创业/企业、国际开发者/访问学者、服务劳动者/通勤者/访客；儿童与老人只在家庭叙述中出现，无障碍使用者只在场景中出现。

v0.6 建议扩展为至少 8 类，并单独形成：

- 老年居民
- 残障 / 行动或感知受限使用者
- 儿童照护者 / 家庭
- 服务劳动者
- 无智能手机 / 不愿注册账号使用者

并建立“受益—负担—排斥风险—非 AI 等价路径—申诉/人工帮助”矩阵。

### D. 缺少 reviewer evidence index

当前证据很多，但需要评审在 proposal、SVG、HTML、矩阵之间自行搜索。v0.6 应增加一张/一表 reviewer evidence index，把：

- 七个 rubric dimensions
- agent.1–agent.6
- 关键 evidence file / section / figure / metric
- claim boundary

做成直接索引。重点是提高**可验证性与表达完整度**，不是自称得分。

### E. 核心可见图需要重新分配信息

v0.6 不应继续只增加 supplemental SVG。要把最高价值证据推到 Review Agent 一定会看到的位置：

## 5. 三个旗舰 pilot 的建议结构

每个 pilot 必须明确这是“待现实条件确认的概念测试协议”，不是已经执行：

- site / user
- real-world problem
- non-AI baseline
- AI enhancement
- accountable role / RACI
- minimum data
- privacy / human review
- prerequisite evidence gates
- time window
- quantity / cost band assumption
- success KPI
- adverse event / failure signal
- automatic stop threshold
- GO / REVISE / STOP decision
- exit / migration / deletion receipt
- public feedback / appeal channel

建议三 pilot：

1. 众智园：低速机器人受控测试 + 人工配送 baseline。
2. AI 原点社区：无障碍/照护导航 + 物理无障碍与人工服务 baseline。
3. 大钟寺：复杂换乘/多语导览 + 静态导视与人工咨询 baseline。
